# Prime Agency CRM

Внутренняя CRM маркетингового агентства: клиенты, оплаты, отчёты по таргету, задачи, команда.
Стек: **Next.js 15 (App Router) + Prisma + SQLite (локально) + Tailwind v4**. Валюта — сом (KGS).

## Запуск

```bash
npm install
npx prisma db push
npm run seed     # демо-данные
npm run dev      # http://localhost:5210
```

## Демо-доступы (пароль `prime2026`)

| Роль | Email | Что видит |
|---|---|---|
| Владелец | owner@prime.kg | всё: финансы, прибыль, команда, аналитика |
| Таргетолог | target1@prime.kg | только свои проекты, их отчёты и задачи |
| Аккаунт-менеджер | account@prime.kg | своих клиентов и статусы оплат (без прибыли) |
| Подрядчик | dev@prime.kg | только доски разработки/монтажа со своими задачами |

## Структура данных

- **User** — сотрудник: роль, ставка (% или фикс), лимит проектов.
- **Client** — клиент: ниша, статус (Тест/Ведётся/Риск оттока/Приостановлен/Отток), услуги, средний чек, таргетолог, аккаунт-менеджер, рекламный кабинет, дата следующей оплаты.
- **Payment** — платёж: тип (абонплата/сайт/бот/монтаж), сумма, статус (Оплачено/Ожидается/Долг), метод, план/факт даты, месяц выручки + снимок распределения (доля исполнителя, резерв, прибыль владельца).
- **AdReport** — отчёт за период: бюджет, потрачено, заявки, целевые действия, целевой CPL/CPA (порог решения), статус связок. CPL/CPA считаются автоматически.
- **Task** — задача: доска (Таргет/Разработка/Монтаж), этап, клиент, ответственный, дедлайн.
- **Notification** — уведомления: приближение оплаты, превышение CPL, новое назначение.
- **Setting** — доли: таргетолог %, разработка %, резерв %, лимит проектов.

## Ролевая модель

Доступ фильтруется на сервере (`src/lib/access.ts`): каждый запрос к клиентам/платежам/отчётам/задачам сужается через `clientScope()` / `taskScope()`, страницы вне роли редиректят на `/no-access`. Прямой заход по чужому `id` даёт 404.

## Финансы

Каждый платёж при сохранении раскладывается: доля исполнителя (34% с абонплаты, 40% с разработки) → резерв на развитие (12%) → остаток = чистая прибыль владельца. Проценты меняются в «Настройках» и применяются к новым платежам.

## Настройки — центр управления

Раздел «Настройки» (владелец) разбит на подразделы:

- **Общие** — доли команды, резерв, лимит проектов, обзор счетов, состояние системы
- **Справочники** — статусы клиентов (с цветом), услуги, источники заявок, ниши, типы и способы оплат, категории расходов и приходов, типы счетов, этапы трёх канбан-досок
- **Сотрудники** — роли, ставки, лимиты, отключение доступа + памятка, что видит каждая роль
- **Уведомления** — за сколько дней предупреждать об оплате, через сколько дней без отчёта напоминать, дедлайн задач и плановых расходов, алерт CPL, кому слать
- **Экспорт** — выгрузка в Excel плитками: клиенты, оплаты, расходы, журнал операций, отчёты, задачи, команда
- **Интеграции** — подключение Telegram-бота, статусы переменных окружения, адрес крона напоминаний

Любое значение справочника можно переименовать, поменять порядок стрелками, скрыть из форм или удалить. Встроенные значения не удаляются — только скрываются, чтобы не сломать уже сохранённые записи. Изменения сразу видны во всех формах и в колонках канбана.

## Счета и журнал операций

Раздел «Финансы и счета»: касса, банковский счёт, карта. Баланс каждого счёта считается из операций (начальный остаток + оплаты клиентов + приходы + переводы на счёт − расходы − переводы со счёта), поэтому не рассинхронизируется. Можно задать минимальный остаток — система предупредит, если баланс ниже.

Там же единый журнал за месяц: оплаты клиентов, прочие приходы, расходы и переводы, с фильтрами по счёту и типу операции. Переводы между счетами не влияют на прибыль.

**Приходы** — деньги не от абонплаты: возврат, партнёрские, внесение своих, прочее. Заводятся кнопкой «Приход», попадают в выручку месяца.

Категории доходов и расходов — справочник: встроенные плюс свои, добавляются в «Настройках».

## День оплаты и договор

У клиента задаётся **день оплаты** (число месяца), даты **договора** и, при работе за процент, **% от прибыли**.

- В списке клиентов — чип «10 числа · через 8 дн.»: красный при ≤3 днях, жёлтый при ≤7, зелёный дальше. Сортировка по умолчанию — по ближайшей оплате.
- Система **сама заводит ожидаемый платёж**: если у активного клиента есть день оплаты, а в текущем месяце абонплаты ещё нет — создаётся платёж «Ожидается» на нужную дату. Дальше работают обычные напоминания.
- После окончания договора платежи не создаются, а за 30 дней до конца приходит напоминание продлить.

## Расходы и прибыль

Раздел «Расходы» (только владелец): категории, статус «оплачен/запланирован», разовые и ежемесячные, привязка к проекту или сотруднику.

Формула месяца: с каждого платежа сначала уходит **доля исполнителя** и **резерв на развитие**, остаток — доля владельца. Из неё вычитаются **расходы месяца** → чистая прибыль. Доля команды и резерв расходами не затрагиваются.

Кнопка «Повторить на след. месяц» копирует все ежемесячные расходы как запланированные. В «Команде» кнопка «Выплатить» записывает начисленную долю сотрудника в расходы (категория «Выплаты команде»).

## Telegram-бот

1. Создать бота у @BotFather, положить токен в переменные окружения:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `APP_URL`, `CRON_KEY`.
2. Указать вебхук: `https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP_URL>/api/telegram&secret_token=<SECRET>`.
3. Сотрудник заходит в CRM → «Профиль» → «Получить код» → отправляет код боту.

Бот шлёт: напоминание сдать отчёт (нет отчёта 7 дней), дедлайн и просрочку задач, приближение и просрочку оплат, алерт при превышении CPL. Прогон напоминаний: при заходе владельца на дашборд и по `GET /api/cron/reminders?key=<CRON_KEY>` (можно вешать на крон раз в день).
Команды бота: `/start`, `/me`, `/tasks`, `/stop`, `/help`.

## Роли и кабинеты

`/dashboard` показывает разное: владельцу — финансы, цели, загрузку команды; остальным — свой кабинет (мои проекты, мои задачи, заявки и CPL, какие проекты ждут отчёт).

## Ставки и распределение

Общие проценты — в «Настройках». Индивидуальная ставка сотрудника на конкретном проекте (процент от чека или фикс за месяц) — в карточке клиента → «Команда проекта».

## Цели

В «Аналитике» ставятся цели на месяц: выручка, прибыль, заявки, клиенты, цена заявки. Цель без клиента — цель агентства (видна на дашборде), с клиентом — план по проекту.

## Деплой (Railway)

1. Переменные: `DATABASE_URL` (Postgres), `JWT_SECRET`.
2. В `prisma/schema.prisma` сменить `provider = "sqlite"` на `"postgresql"`.
3. `npm run build` уже выполняет `prisma db push`.
